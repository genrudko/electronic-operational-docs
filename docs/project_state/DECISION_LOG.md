# ЭОД — журнал решений

Записи добавляются по времени. Исправление решения оформляется новой записью, старое не удаляется.

## 2026-07-22 — единое ядро структурированных журналов

Оперативный журнал остаётся специализированным модулем. Остальные журналы строятся поверх
общего ядра: тип документа, публикуемая схема, запись, поля, статусы, участники, оборудование,
документы, связи, редакции, аудит, поиск и фильтры.

## 2026-07-23 — Patch 011.6 завершён

Приняты импорт оборудования, персонала, оперативных прав и реестра документации рабочего места.
Импорт документации явно привязывается к активному рабочему месту; исходная неоднозначность
не исправляется молча.

## 2026-07-23 — двухфазная непрерывность контекста

Чат не является единственным носителем состояния проекта.

- перед каждым Patch/Repair создаётся pre-patch snapshot;
- после каждого визуально принятого Patch/Repair обновляется `EOD_CURRENT_CONTEXT.zip`;
- стартовый текст нового чата хранится внутри пакета и рядом с ним;
- постоянный реестр состояния хранится в `docs/project_state/`.

## 2026-07-23 — Patch 011.7 не зашивает конкретные журналы

Patch 011.7 реализует механизмы общего ядра. Конфигурации журналов заявок, распоряжений,
работ, дефектов, ввода оборудования, РЗА/телемеханики и ключей относятся к Patch 011.8.

## 2026-07-23 — snapshot проверяется по содержанию, а не по заранее зашитому SHA

Повторная корректная сборка ZIP меняет его SHA-256 из-за времени создания и состава
диагностических файлов. Патч обязан проверять, что фактический SHA совпадает с
собственным marker и `.sha256`, а внутренний manifest подтверждает нужные branch,
HEAD, clean worktree и ID предстоящего патча. Заранее зашивать SHA одной конкретной
сборки snapshot запрещено.

Файловый patch-лог подключается сразу после определения project root и до всех
preflight-проверок, чтобы любой контролируемый отказ сохранялся в `logs/`.

## 2026-07-23 — текстовые payload проверяются целиком до выдачи

Все встроенные текстовые payload-файлы автономного патча должны использовать только LF,
завершаться ровно одним переводом строки и проходить полный цикл декодирования, SHA-256
и проверки окончаний для всего `EXPECTED_PATHS` до публикации файла пользователю.
