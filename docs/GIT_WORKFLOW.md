# Git workflow

## Репозиторий

- Ветка: `main`.
- GitHub: `genrudko/electronic-operational-docs`.
- Допустимая видимость: только `private`.
- Реальные инструкции, рабочие документы, экспорты чатов и проектные материалы
  хранятся вне Git-репозитория.

## Обязательное правило

Патч коммитится и отправляется только после успешного прохождения всех
функциональных и качественных gate-проверок.

- Ошибка любого gate: commit и push запрещены.
- Успешный commit при ошибке push остаётся локально и фиксируется в логе.
- Один успешный патч или repair-патч: один commit.
- Тестовый запуск, обнаруживший ноль тестов или меньше установленного порога,
  считается ошибкой.
- Обычный force-push в `main` запрещён.
- Единственное выполненное исключение — Patch 006.2, который переписал историю,
  чтобы удалить ошибочно добавленные реальные документы. После завершения этого
  патча force-push снова запрещён.

## Разрешённые пути

Автоматический helper принимает изменения только в следующих областях:

- `src/`;
- `scripts/`;
- `docs/`;
- строго определённые корневые файлы проекта.

Проверка применяется ко всем staged-путям, включая уже отслеживаемые изменения и
удаления. Наличие файла в старой истории больше не позволяет обойти allowlist.

Всегда блокируются:

- `.env`, базы данных, логи, резервные копии и ключевые файлы;
- каталог `Инструкции/`;
- `ChatGPT-*.md`;
- `EOD_full_project_plan_v2_*.md`;
- офисные документы, PDF и архивы.

Если проекту позднее потребуется безопасный тестовый бинарный fixture, его следует
добавлять отдельным патчем с точным исключением, происхождением и проверкой
содержимого, а не ослаблять общую политику.

## Стандартный helper

Основной патч вызывает helper автоматически. Ручной запуск:

```powershell
.\.venv\Scripts\python.exe scripts\git_finalize_patch.py `
  --root "G:\electronic-operational-docs" `
  --patch-id "patch_xxx" `
  --message "Describe the change"
```

Helper:

1. проверяет ветку и точный `origin`;
2. через GitHub CLI убеждается, что репозиторий закрыт;
3. проверяет `git diff --check`;
4. проверяет allowlist для всех изменённых и staged-путей;
5. добавляет только допустимые новые файлы;
6. блокирует локальные данные, документы и секреты;
7. создаёт commit;
8. повторно проверяет приватность и выполняет обычный push в `main`.
