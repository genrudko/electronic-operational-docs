# ЭОД — политика данных и приватности

## 1. Базовый принцип

Репозиторий является закрытым, но не считается хранилищем секретов, производственных данных или документов предприятия.

Private visibility снижает риск случайного раскрытия, но не отменяет минимизацию данных.

## 2. Разрешено хранить в Git

- исходный код;
- migrations;
- tests and gates;
- безопасные fixtures с вымышленными данными;
- архитектурную и процессную документацию;
- технические IP-адреса, порты, пути и имена сервисов;
- команды runbook без секретных значений;
- ADR, plans, acceptance evidence summaries;
- публичные нормативные реквизиты и собственные аналитические выводы без копирования защищённых материалов.

## 3. Запрещено хранить в Git

- действующие passwords, tokens, API keys, private keys и certificates;
- содержимое `.env`;
- PostgreSQL dumps, SQLite databases и backups;
- реальные Ф.И.О. работников и персональные контакты;
- фактические оперативные записи;
- реальные матрицы прав и допусков;
- внутренние инструкции, распоряжения, PDF/XLSX/CSV предприятия;
- архивы чатов и контекстные пакеты с чувствительными материалами;
- production logs;
- материалы с неподтверждёнными правами распространения.

## 4. Presentation data

Presentation profile должен:

- использовать вымышленные Ф.И.О.;
- не воспроизводить фактическое распределение полномочий;
- не содержать реальные номера внутренних документов;
- не содержать актуальные производственные события;
- быть пригодным для демонстрации сквозных сценариев;
- восстанавливаться повторяемым контролируемым способом.

Публично узнаваемое название объекта может использоваться как демонстрационный контекст только при отсутствии чувствительных производственных сведений.

## 5. Исследовательские источники

Реальные документы могут быть предоставлены ассистенту вне Git для анализа. Результат в репозитории должен содержать:

- ссылочное описание источника;
- собственную структуру данных или traceability matrix;
- минимально необходимые реквизиты;
- отсутствие копии исходного файла и чувствительного содержимого.

## 6. Секреты VPS

```text
/srv/eod/secrets/preview.env
/srv/eod/secrets/development.env
```

Требования:

- owner `root:root`;
- mode `0600`;
- отдельные значения для preview и development;
- значения не печатаются в чат и logs;
- ротация выполняется при компрометации или плановом security event, а не ради формальности.

## 7. SSH keys

- VPS deploy key остаётся read-only;
- write operations выполняются через GitHub connector/account;
- private key не коммитится и не пересылается как содержимое сообщения;
- при потере доверия к ключу он отзывается и заменяется.

## 8. Логи и артефакты CI

CI logs не должны выводить secrets. Failure artifacts имеют ограниченный retention и содержат только диагностику, необходимую для анализа.

Перед добавлением нового artifact проверяется:

- какие данные он включает;
- кто имеет доступ;
- срок хранения;
- необходимость redaction.

## 9. Backup

Backups хранятся вне Git. Для каждого backup должны быть известны:

- источник;
- дата и baseline;
- checksum или иной контроль целостности;
- путь хранения;
- процедура восстановления;
- политика удаления.

## 10. Обнаружение нарушения

При обнаружении секретного или реального чувствительного файла:

1. прекратить распространение и использование;
2. оценить, был ли секрет действующим;
3. отозвать/заменить скомпрометированный секрет;
4. удалить файл из текущей ветки;
5. при попадании в историю решить вопрос о history rewrite отдельно;
6. зафиксировать инцидент без повторного раскрытия значения;
7. добавить предотвращающий gate.

## 11. Официальный пилот

Переход к реальным данным возможен только после отдельного решения о:

- законном основании обработки;
- владельце данных;
- ролях доступа;
- инфраструктуре;
- backup and retention;
- audit and incident response;
- правах на код и эксплуатационной ответственности.
