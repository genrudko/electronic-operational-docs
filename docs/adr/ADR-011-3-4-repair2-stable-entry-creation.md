# ADR-011-3-4 Repair 2 — устойчивое создание записей и встроенный ввод ПЗ

## Статус

Принято для независимого прототипа ЭОД.

## Контекст

После визуальной приёмки Patch 011.3.4 выявлены взаимосвязанные дефекты интерфейса журнала:

- удалённая строка временно продолжала занимать расчётное место страницы;
- активная пустая строка не считалась режимом редактирования и могла быть уничтожена пагинацией;
- создание записи требовало попадания в маленькую кнопку `+`;
- пагинация могла заходить под закреплённую панель редактора;
- преобразование сокращённого времени зависело от конкретной последовательности клавиатурных событий;
- номер ПЗ и выбор исходной отметки выполнялись нативными браузерными диалогами;
- панель восстановления нельзя было закрыть сразу, а на границе таймера она могла оставаться с `0 с`.

## Решение

1. Pending soft-delete немедленно освобождает визуальное место для новой записи, не дожидаясь окончания периода восстановления.
2. Активное inline-создание получает владение пагинацией до сохранения или отмены.
3. Вся свободная строка становится доступной мышью и клавиатурой точкой создания записи.
4. Положение sticky-пагинации вычисляется по фактической высоте верхнего header и командной панели; изменение высоты отслеживается `ResizeObserver`.
5. Упрощённое время обрабатывается до вставки разделителя через `beforeinput` и повторно после ввода как fallback.
6. Ввод номера ПЗ и выбор исходной отметки реализуются внутри нормативного меню безопасными DOM-элементами без `prompt()` и `innerHTML`.
7. Панель восстановления получает кнопку `×`; достижение нуля гарантированно завершает placeholder через microtask.

## Последствия

- схема базы данных не меняется;
- существующие записи и ревизии не переписываются;
- soft-delete и десятисекундное восстановление сохраняются;
- пользователь может продолжить ввод сразу после удаления записи;
- интерфейс ПЗ становится единообразным с остальным редактором;
- исправления должны быть подтверждены браузерной визуальной приёмкой до перехода к Patch 011.4.
