# ADR-002: персональные учётные записи и организационная область полномочий

## Статус

Принято для Stage 1.

## Решение

1. На этапе прототипа используется стандартная модель пользователя Django.
2. Оперативная идентичность представлена отдельной моделью `Employee`.
3. Связь `Employee.user` имеет тип one-to-one: одна персональная учётная запись не может быть общей для нескольких сотрудников.
4. Пользователь без связанного активного сотрудника может пройти техническую аутентификацию, но не получает оперативных ролей.
5. Роли назначаются сотруднику на ограниченный срок и, при необходимости, на `ResponsibilityScope`.
6. Временное замещение не копирует и не изменяет назначения ролей. Эффективные полномочия вычисляются на заданную дату через действующее `Substitution`.
7. Успешный вход, неуспешный вход и выход фиксируются в `AuthenticationEvent`.
8. Факт входа не считается электронной подписью. Повторное подтверждение личности и подписывающие реквизиты реализуются отдельным этапом.

## Ограничения текущего этапа

- тестовые пользователи и сотрудники являются вымышленными;
- нет интеграции с AD/LDAP/ЕСИА или корпоративными каталогами;
- нет квалификаций, специальных прав и проверки знаний;
- нет криптографической подписи;
- SQLite используется только в локальном профиле разработки.
