# ADR-011.3 Repair 2 — тип записи и встроенные ссылки

## Решение

Семантика разделена на два пользовательских механизма.

### Тип всей записи

К одной записи применяется один тип:

- обычная запись;
- команда;
- разрешение;
- сообщение;
- предупреждение;
- на следующую смену.

Тип выбирается мгновенно в mini-ribbon и хранится в корне документа редактора как `entry_kind`. Повторный ввод текста и модальное окно не используются.

### Связанные объекты внутри текста

Оборудование, документ, сотрудник, время события и другая запись оформляются как встроенная ссылка внутри обычного текста. Оператор может:

1. выделить уже набранный фрагмент и связать его с объектом;
2. поставить курсор и вставить наименование выбранного объекта;
3. открыть существующую связь двойным щелчком;
4. снять связь без удаления видимого текста.

Для выбора реального объекта используется компактный popover рядом с текстом, а не модальный диалог. Каталог ограничен организацией текущего журнала.

## Схема

Текущая версия: `operational-draft-editor.v3`.

```json
{
  "schema_version": "operational-draft-editor.v3",
  "entry_kind": "command",
  "blocks": [
    {
      "type": "paragraph",
      "segments": [
        {"text": "Отключить ", "marks": []},
        {
          "text": "В-35 Т-1",
          "marks": [],
          "reference": {
            "kind": "equipment",
            "label": "В-35 Т-1",
            "reference": "equipment:<uuid>"
          }
        }
      ]
    }
  ]
}
```

Текстовая проекция: `Команда: Отключить В-35 Т-1`.

## Совместимость

Документы `v1` и `v2` принимаются. При нормализации:

- старые команды, разрешения, сообщения, предупреждения и переносы становятся `entry_kind`;
- оборудование, документы, сотрудники, время и связанные записи становятся inline-reference;
- видимый текст сохраняется;
- данные обновляются до `v3` при штатном сохранении записи.

## Печать

В печати интерфейсные метки и подчёркивания скрываются. Тип записи выводится обычным текстовым префиксом, а связанные объекты остаются читаемым текстом.
