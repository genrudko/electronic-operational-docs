# ADR-011-3-4 Repair 4: атомарное восстановление положения журнала

## Статус

Принято для независимого демонстрационного прототипа.

## Контекст

Визуальная проверка Repair 3 подтвердила корректную красную аварийную
обводку, снятие аварийной отметки и завершение редактирования кликом за
пределами полотна. При этом после `Ctrl+Enter` и после outside-click
оставался заметный скачок: журнал сначала показывал промежуточную
позицию после повторной раскладки строк, а затем возвращал исходный
визуальный якорь.

Причина состояла из двух частей:

1. асинхронный `save()` мог запустить обычный хронологический reveal,
   когда фокус уже покинул форму, хотя транзакция завершения ещё шла;
2. возврат scroll-anchor выполнялся только через
   `requestAnimationFrame`, поэтому браузер мог отрисовать
   промежуточное положение row store.

## Решение

- Пока `form.dataset.finishing == "true"`, `save()` только помечает
  хронологическую перестройку как ожидающую и не запускает обычный
  `scrollIntoView`.
- Завершение записи применяет перестройку через путь
  `scroll: false` с переданным viewport-anchor.
- Первая коррекция scroll-anchor выполняется синхронно в том же
  JavaScript-такте, сразу после перестройки DOM.
- Последующие две коррекции выполняются в соседних кадрах для учёта
  отложенного снятия editor-классов и изменения высоты строки.
- Все программные возвраты используют `behavior: "auto"`.

## Инварианты

- `Ctrl+Enter`, Escape и outside-click не должны менять видимую позицию
  выбранной строки.
- Явный переход к связанной записи по-прежнему может использовать
  плавное центрирование.
- Модель данных и схема БД не изменяются.
