# ADR-007.2: презентационный UX и безопасный демонстрационный профиль

- Статус: принято
- Дата: 2026-07-16
- Базовая линия: Patch 007 (`8bdb593df14288aeb89139887740aa495ae82876`)

## Контекст

Предметная модель управления и ведения прошла автоматическую и визуальную проверку,
но пользовательские страницы оставались похожими на административный вывод базы
данных. На первом плане находились внутренние коды, SHA-256, номера редакций и
служебные подписи этапов разработки. Демонстрационные названия вида «Демо-ВЭС»
мешали понимать сценарий презентации.

## Решение

1. Основной интерфейс показывает субъект, функцию, уровень и период простым языком.
2. Внутренние коды, SHA-256, номера редакций и диагностика скрыты по умолчанию.
3. Технические сведения не удаляются и включаются персональной настройкой.
4. Исторические таблицы и основания помещаются в раскрываемые блоки.
5. Таблица распределения заменяется карточками объектов с отдельными дорожками
   управления и ведения.
6. Добавляется локальный SVG-спрайт иконок без внешних CDN и сетевых зависимостей.
7. Настройки темы, плотности, размера текста, ширины и технического режима хранятся
   в профиле учётной записи.
8. Демонстрационный профиль использует узнаваемое публичное название
   «Кочубеевская ВЭС», но не копирует фактические схемы полномочий, персональные
   данные работников, реальные номера документов или оперативные сведения.
9. ФИО демонстрационных сотрудников остаются вымышленными, но выглядят естественно.
10. Стабильные системные коды `DEMO-*` сохраняются и видны только в техническом режиме.

## Последствия

- страницы пригодны для визуальной демонстрации без потери прослеживаемости;
- предметная модель Patch 007 не меняется;
- пользователь может самостоятельно выбрать удобную плотность и масштаб;
- импорт Patch 008 сможет наполнять реестр без возвращения к перегруженной таблице;
- презентационные данные нельзя трактовать как действующее оперативное распределение.

## Уточнение Repair 1: презентационные подписи

Уровни и субъекты, уже использованные опубликованными редакциями Patch 007,
не переименовываются. Узнаваемые подписи презентационного профиля формируются
в пользовательском слое по стабильным кодам демонстрационного контура. Тем самым
интерфейс показывает понятные наименования, а зафиксированная предметная история
остаётся неизменной.

## Уточнение Repair 3: тестовый контракт представления

Старые проверки, привязанные к словам `Демо-ВЭС`, `Демо-РДЦ` и к
отладочному блоку главной страницы, заменены проверками пользовательского
представления. Проверка неизменности снимка оборудования больше не зависит
от фиксированного номера следующей редакции: используется следующий свободный
номер, а сравнение выполняется с фактически зафиксированным снимком.

## Уточнение Repair 4: контракт gate оборудования

Gate Patch 006 сохраняет проверку исторического наименования
`КТП-1 Демо-ВЭС`, но текущее диспетчерское наименование сверяет с
опубликованной презентационной редакцией `КТП-01 Кочубеевской ВЭС`.
Изменение относится только к ожидаемому текущему значению gate и не
ослабляет проверки неизменяемости, снимков документов, алиасов и иерархии.

## Уточнение Repair 5: локальная финализация без автоматического push

На этапе активной разработки Patch 007.2 финализируется локальным Git commit.
Автоматический push в `origin/main` отключён: он выполняется только отдельной
явной командой после визуальной приёмки или накопления проверенного набора
изменений. Локальные тесты, gate, точный staged-контракт и чистота рабочего
дерева сохраняются обязательными.
