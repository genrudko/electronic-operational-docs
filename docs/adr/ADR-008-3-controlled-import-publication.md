# ADR-008.3: контролируемая публикация импорта

## Статус

Принято для независимого демонстрационного прототипа.

## Контекст

Patch 008.1 создал изолированную staging-зону, а Patch 008.2 добавил сопоставление
колонок, повторную проверку данных и предварительные решения по строкам. До Patch
008.3 ни одно действие модуля импорта не записывало данные в рабочие справочники.

Переход из staging в рабочий реестр является необратимым деловым действием. Он
должен быть отделён от проверки строк, выполняться только уполномоченным
сотрудником и оставлять неизменяемый доказуемый след.

## Решение

1. Публикуются только строки с решением `ACCEPTED`; строки `REJECTED` сохраняются в
   истории и пропускаются. Наличие `PENDING` блокирует публикацию.
2. Публикация поддерживается для справочников организации и персонала,
   оборудования, управления и ведения. Назначение «Другой справочник» остаётся
   staging-only до определения целевой модели.
3. Полномочие требует прямого действующего назначения роли
   `organization_admin`. Замещение оперативной роли не передаёт административное
   право публикации.
4. Перед записью пользователь видит точный список создаваемых объектов,
   канонический снимок и SHA-256, повторно вводит текущий пароль и явно подтверждает
   действие.
5. Вся запись выполняется одной транзакцией с повторной проверкой ссылок,
   конфликтов и SHA-256. При ошибке не создаётся ни одной целевой записи.
6. Импорт не обновляет существующие объекты. Совпадение с рабочим реестром является
   конфликтом и требует нового решения вне этого патча.
7. Результат фиксируется моделями `ImportPublication` и
   `ImportPublicationRow`. Снимок, автор, время, целевые идентификаторы и SHA-256
   неизменяемы. Повторная публикация одной загрузки запрещена.
8. Для оборудования при наличии диспетчерского наименования создаётся и
   публикуется отдельная редакция через существующий сервис реестра. Для управления
   и ведения используются существующие серверные сервисы публикации редакций.
9. После успешной публикации сопоставление, решения и удаление загрузки из рабочего
   списка блокируются.

## Последствия

- Рабочие реестры изменяются только на отдельном экране подтверждения.
- Ошибка или изменение реестра между просмотром и подтверждением приводит к полному
  откату транзакции.
- Появляется неизменяемая связь между исходным файлом, решениями по строкам и
  созданными объектами.
- Patch 008.3 не реализует обновление существующих записей, отмену опубликованных
  объектов или универсальную публикацию произвольных справочников.
