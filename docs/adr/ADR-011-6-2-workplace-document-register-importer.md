# ADR-011.6.2 — Импорт реестра документации рабочего места

**Статус:** принято для реализации Patch 011.6.2
**Дата:** 23.07.2026
**Baseline:** `main / b70349b190d582f66ff20bad94dfa26d5ac78184 / clean`

## Контекст

Аналитический контур Patch 011.6 подготовил файл
`eod_workplace_document_register.csv` на основании перечня документации рабочего
места оперативного персонала Кочубеевской ВЭС. Источник содержит 66 позиций в
12 разделах, реквизиты утверждения, предложенную классификацию, периодичность,
страницу исходного PDF и исходную отметку электронной формы.

Существующее приложение `workplace_docs` уже содержит доменную модель перечня,
неизменяемых редакций, позиций, утверждения и истории. Создание второго рабочего
справочника запрещено: импорт обязан публиковать данные в существующую модель.

## Решение

Patch 011.6.2 добавляет специализированный технический импортёр одного CSV:

1. исходный файл принимается только в development-базе;
2. разрешён только профиль `local-validation` с запрещённым обычным экспортом;
3. проверяются UTF-8/UTF-8 BOM и точный фактический заголовок из 18 колонок;
4. исходные байты не сохраняются;
5. создаются staging-редакция, строки и неизменяемый снимок публикации;
6. сохраняются исходные и нормализованные номера, даты, периодичность и отметки;
7. конфликтные значения не исправляются молча, а переводятся на проверку или блокируются;
8. каждая строка `REVIEW_REQUIRED` требует аудируемого решения: принять исходное
   значение с обоснованием либо исключить позицию из публикации;
9. заблокированные строки нельзя обойти решением — требуется исправленный источник;
10. готовые строки публикуются в `WorkplaceDocumentList`,
   `WorkplaceDocumentRevision` и `WorkplaceDocumentEntry`;
11. утверждение выполняется существующим сервисом `approve_revision`;
12. ошибочная staging-редакция исключается из рабочего списка без физического удаления.

## Контракт заголовка

```text
register_entry_no,section_no,section_name,subsection_no,subsection_name,
source_document_no,document_title_raw,document_type_proposed,
electronic_storage_mark,electronic_storage_interpretation,review_period_raw,
review_interval_years_proposed,approval_date_from_title_page,
approving_role_from_title_page,approver_from_title_page,workplace_scope,
source_pdf_page,source_notes
```

Строка выше разбита для чтения ADR; программный контракт хранит те же 18 полей
в одном упорядоченном tuple. Внутренний `source_index` вычисляется по физическому
порядку строк CSV и не является колонкой внешнего формата.

## Предметные ограничения

- `+ / INDICATED` означает только то, что электронная форма указана в источнике.
- Это не доказывает наличие электронного файла и не отменяет бумажный экземпляр.
- `- / NOT_INDICATED` не является запретом электронной копии.
- Ни `+`, ни `-` не определяют доменное поле формы хранения: при публикации оно
  остаётся `UNKNOWN`, а исходная отметка хранится отдельными полями.
- Неизвестная или противоречивая пара отметки блокируется.
- Текстовая периодичность и числовое предложение хранятся одновременно.
- Номер раздела, подраздела, сквозной позиции и номер внутри раздела не сливаются.
- Повтор номера внутри одного раздела/подраздела и пропуски нумерации требуют проверки.
- Исторические названия организаций в заголовках документов не переписываются.
- Содержимое самих документов и сканы в Patch 011.6.2 не загружаются.

## Сопоставление рабочего места

Источник использует название «Рабочее место оперативного персонала
Кочубеевской ВЭС», а демонстрационная организационная модель использует код
`KOCH_CONTROL_ROOM` и название «Главный щит управления Кочубеевской ВЭС».
Разрешён один явный контролируемый алиас. Автоматическое нечёткое сопоставление
не выполняется.

В реальной development-базе контролируемый алиас может не иметь соответствующего
активного рабочего места. Поэтому техническая форма загрузки требует явного выбора
действующего рабочего места назначения. Если точное или контролируемое автоматическое
сопоставление найдено, ручной выбор обязан совпадать с ним; противоречащий выбор
отклоняется. Если автоматическое сопоставление отсутствует, выбор сохраняется как
`MANUAL_SELECTION` вместе с кодом рабочего места в манифесте происхождения.

Контекст идемпотентности включает сопоставленное рабочее место. Это позволяет
повторно загрузить тот же неизменяемый источник для корректного рабочего места,
не изменяя и не удаляя ранее созданную заблокированную staging-редакцию.

## Публикация

Публикация:

- требует прямой действующей роли `organization_admin`;
- требует повторного ввода текущего пароля в web-интерфейсе;
- проверяет SHA-256 предварительного состава;
- включает только строки `READY`;
- блокируется, пока существуют `REVIEW_REQUIRED` или `BLOCKED`;
- разрешает перевести `REVIEW_REQUIRED` в `READY` только явным решением
  `ACCEPT_AS_IS` с автором, временем и обоснованием;
- разрешает исключить только изначально неоднозначную строку явным решением
  `EXCLUDE`; изначально готовые и заблокированные строки через этот механизм
  исключить нельзя;
- позволяет сбросить решение и восстановить исходное состояние проверки;
- создаёт новую утверждённую доменную редакцию;
- записывает `paper_storage_waivers_created = 0`;
- сохраняет источник, разделы, тип, периодичность, утверждение, страницу PDF
  и аудит ручных решений в каноническом снимке публикации;
- после публикации пересчитывает технические состояния строк: счётчик `READY`
  обнуляется, а строки доступны по отдельному фильтру `PUBLISHED`.

## Безопасность тестовых данных

В Git и payload патча включены только синтетические сотрудники, организация,
рабочее место и две синтетические строки CSV. Реальный CSV, реальные ФИО и
исходный скан не включён в patch, migrations, tests или documentation payload.
Фактический файл используется пользователем только в локальной development-базе.

## Граница релизного UX

Этот интерфейс остаётся расширенным техническим контуром. Финальный релизный
мастер должен принимать исходные файлы без знания внутреннего CSV-контракта,
автоматически формировать нормализованный пакет и показывать пользователю только
изменения и неоднозначности.
