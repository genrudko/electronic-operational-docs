# ADR-INFRA-002 — закрытый контейнерный preview на VPS

**Статус:** предложено для проверки
**Дата:** 24.07.2026

## Контекст

После принятия GitHub Actions CI проекту нужен воспроизводимый Linux/PostgreSQL preview,
доступный владельцу проекта без публикации приложения в интернет.

Исходный `compose.yaml` предназначен для локальной разработки: он запускает только PostgreSQL,
публикует порт базы на хост и содержит development fallback-пароль. Использовать этот файл как
серверный контур запрещено.

## Решение

Создаётся отдельный `compose.preview.yaml` со следующими свойствами:

- Django работает под Gunicorn в отдельном image;
- статические файлы обслуживаются WhiteNoise;
- приложение запускается непривилегированным пользователем;
- PostgreSQL 18.4 не публикует порт на хост;
- volume PostgreSQL монтируется в `/var/lib/postgresql`, как требуется образом PostgreSQL 18+;
- приложение публикуется только на `127.0.0.1:8765`;
- доступ выполняется через SSH-туннель;
- секреты передаются из `/srv/eod/secrets/preview.env` и не хранятся в Git;
- preview прекращает запуск при development secret, включённом DEBUG, SQLite или fallback-пароле;
- migrations и collectstatic выполняются entrypoint перед Gunicorn;
- health endpoint проверяет HTTP и доступность базы;
- GitHub Actions собирает образ, поднимает весь stack и выполняет smoke-test до deployment на VPS.

## Границы

INFRA-002 не включает:

- публичный домен;
- HTTPS и reverse proxy;
- автоматический deployment;
- промышленный мониторинг;
- production secrets management;
- изменение существующей локальной базы;
- миграцию данных из локального `compose.yaml`.

## Безопасность

- порт PostgreSQL отсутствует в host mappings;
- порт приложения привязан только к loopback;
- контейнер приложения работает без root;
- применяется `no-new-privileges`;
- реальные секреты не передаются в GitHub и не коммитятся;
- deploy key VPS остаётся read-only;
- merge в `main` выполняется только после CI и визуальной проверки preview.

## Последствия

Положительные:

- разработка проверяется в том же классе окружения, что и серверный preview;
- Linux/PostgreSQL и контейнерные дефекты выявляются до предметных патчей;
- владелец проекта может проверять feature-ветку через обычный браузер и SSH-туннель.

Ограничения:

- preview остаётся независимым прототипом и не является производственной системой;
- database backup/restore и автоматический deployment оформляются отдельными этапами;
- существующий локальный PostgreSQL volume требует отдельной безопасной миграции из-за изменения
  пути данных в PostgreSQL 18.
